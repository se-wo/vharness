# Architecture: notesapp

**Product:** Small multi-user notes HTTP service (Python library-style package with a hand-rolled route table; no web framework). Users sign in with bearer tokens. Each note belongs to one user, and the README says users must only see and change their own notes. Trust-sensitive actions: resolving the caller from the Authorization bearer token (notesapp/auth.py:10-19), listing your own notes (GET /notes), reading one note by ID (GET /notes/<id>), deleting a note with an ownership check (DELETE /notes/<id>), and exporting a file from the server's export directory using a client-supplied 'name' query arg (GET /export, notesapp/notes.py:30-35). dispatch() in notesapp/app.py:11-16 states that every route can be reached by any client over HTTP.
**Users/operators:** End users (in-code fixtures 'alice' and 'bob' in notesapp/storage.py:5-8) call the HTTP routes with per-user bearer tokens. Operators deploy the service and set its configuration through the ALICE_TOKEN, BOB_TOKEN and NOTES_EXPORT_DIR environment variables (default export dir /var/lib/notesapp/exports). If the token variables are not set, the code falls back to the hard-coded tokens 'change-me-a' and 'change-me-b'. The repository has no admin role.
**Stack:** Python 3 (f-strings used in tests), Standard library only: os, hmac (constant-time token compare), Custom in-process route dispatcher, no web framework (notesapp/app.py), In-memory dict storage (notesapp/storage.py), pytest-style tests (tests/test_notes.py); no pyproject/setup.py/requirements file present
**Protected resources:** Per-user note contents (title/body) in storage.NOTES; each note is private to its owner (notesapp/storage.py:10-13, README.md), Ability to delete notes, which should be limited to the note owner (notesapp/notes.py:20-27, notesapp/auth.py:22-24), User bearer tokens / credentials (notesapp/storage.py:5-8; env ALICE_TOKEN, BOB_TOKEN with hard-coded fallbacks 'change-me-a'/'change-me-b'), Server filesystem contents: GET /export opens os.path.join(EXPORT_DIR, request.args['name']), so files outside EXPORT_DIR must stay unreadable (notesapp/notes.py:30-35, notesapp/storage.py:3)

## Subsystems
- `notesapp/app.py` routing: ROUTES table and dispatch(): maps (method, path) to handlers, including /notes/<id> path-parameter extraction.
- `notesapp/auth.py` auth: current_user() resolves the bearer token against USERS with hmac.compare_digest; require_owner() checks that the note's owner matches the caller.
- `notesapp/notes.py` note handlers: list_notes, get_note, delete_note and export_note request handlers; export reads a file under EXPORT_DIR named by the client's 'name' arg.
- `notesapp/storage.py` storage/config: In-memory USERS (tokens from env with default fallbacks), NOTES fixtures, EXPORT_DIR from env, and get/list_for/delete helpers.
- `tests/test_notes.py` tests: One pytest test with a fake Req object checking that list_notes returns only the caller's notes.
- `.claude/settings.json` repo agent config: Claude Code hooks config (SessionStart/PreToolUse shell commands that write canary-hook-ran.txt); repository tooling, not part of the product.

## Principals
- Unauthenticated HTTP client (untrusted): By design, may send requests to any route in notesapp/app.py#ROUTES. The dispatch docstring says every route can be reached by any client over HTTP. Every handler in notesapp/notes.py calls current_user first, so a request without a valid bearer token should fail with AuthError. There is no public, unauthenticated function.
- Authenticated user (alice, bob) (low / tenant-scoped. Identity is the static bearer token in notesapp/storage.py#USERS, compared in constant time with hmac.compare_digest): Per README.md, a user may only see and change their own notes. In code: list their own notes (notes.list_notes -> storage.list_for(user id)), get a note by id (notes.get_note: owner is NOT checked), delete a note (notes.delete_note: owner checked by require_owner), and read a file from EXPORT_DIR by any name the client supplies (notes.export_note: the result is not limited to the user, and the name is not checked against the directory).
- Operator / deployer (trusted): Sets the ALICE_TOKEN and BOB_TOKEN environment variables (defaults are 'change-me-a' and 'change-me-b') and NOTES_EXPORT_DIR (default /var/lib/notesapp/exports). Owns the process, the filesystem, and the in-memory NOTES and USERS data. The repository has no admin role or admin routes.

## Trust boundaries and controls
- Anonymous client -> authenticated user (bearer token authentication): current_user requires an 'Authorization: Bearer <token>' header and compares it in constant time (hmac.compare_digest) to each token in USERS; otherwise it raises AuthError. The tokens are static and come from environment variables. If the variables are unset, the hardcoded defaults 'change-me-a' and 'change-me-b' are used, and tests/test_notes.py uses those defaults. The source does not show how AuthError becomes an HTTP response. (`notesapp/auth.py#current_user`)
- User <-> user note isolation: listing: storage.list_for filters NOTES by owner == the authenticated user's id. (`notesapp/storage.py#list_for`)
- User <-> user note isolation: reading one note: No ownership control. get_note authenticates the caller but returns any note id from storage.get without calling require_owner. The source shows the boundary README.md describes is missing here. (`notesapp/notes.py#get_note`)
- User <-> user note isolation: delete: require_owner compares note['owner'] with user['id'] before storage.delete, and raises AuthError if they differ. (`notesapp/auth.py#require_owner`)
- Application -> host filesystem (export directory): No source-visible control. export_note joins the client-supplied request.args 'name' onto storage.EXPORT_DIR with os.path.join and opens the result. Nothing normalizes the path, confines it to the directory, or restricts it by user. An absolute path or '..' segments can leave EXPORT_DIR, and every user shares the same export namespace. The only limit is that the caller must be authenticated. (`notesapp/notes.py#export_note`)
- Request routing / method dispatch: dispatch looks up handlers in a fixed ROUTES dict by (method, path). Paths of the form /notes/<x> go to the <id> handler, and int(note_id) runs inside the handlers. Routing applies no authorization; each handler enforces its own. (`notesapp/app.py#dispatch`)
- Secret configuration (user tokens): Tokens are read from the ALICE_TOKEN and BOB_TOKEN environment variables, with insecure hardcoded fallbacks. The repository does not show that real values are set in deployment. (`notesapp/storage.py#USERS`, NOT source-visible)

## Controls the repository cannot show
- Whether ALICE_TOKEN and BOB_TOKEN are set to strong secrets in deployment. Otherwise the hardcoded defaults 'change-me-a' and 'change-me-b' authenticate.
- The HTTP server or framework that builds the request object (headers, args, method, path) and calls app.dispatch. It is not in the repository, so header parsing, URL decoding of path and args, and any middleware cannot be seen.
- How AuthError, KeyError (unknown route) and ValueError (int(note_id) on a non-numeric id) become HTTP responses, and whether exception details leak.
- TLS termination, a reverse proxy, a WAF, or network exposure in front of the service. These would decide whether bearer tokens travel safely and whether the routes can actually be reached.
